# Oberon

[](https://github.com/oberon-core/oberon/actions/workflows/build.yml) [![Version](https://img.shields.io/badge/version-0.4.3-6f42c1)](https://github.com/oberon-core/oberon) [![Go](https://img.shields.io/badge/Go-1.25%2B-00ADD8?logo=go)](https://go.dev/)
**کلاینت AmneziaWG WARP برای مدیریت پروفایل، اسکن اندپوینت و پراکسی محلی امن**

[🌐 English](README.md) · [فارسی](README.fa.md)

🌐 Oberon پروفایل WARP را می‌سازد و نگه می‌دارد، اندپوینت‌هایی را که هندشیک AmneziaWG موفق دارند بررسی می‌کند و از طریق پراکسی SOCKS5 و HTTP یا تونل سراسری به آن‌ها وصل می‌شود.

## ✨ امکانات

- 🪄 **راه‌اندازی خودکار بار اول:** اگر پروفایل معتبری پیدا نشود، TUI فقط یک‌بار حساب WARP را ثبت و پروفایل را ذخیره می‌کند؛ اتصال‌های بعدی همان کلید را استفاده می‌کنند.
- 🔎 **اسکن در هر اتصال:** اندپوینت‌ها پیش از اتصال آزمایش می‌شوند، پیشرفت اسکن نمایش داده می‌شود و سریع‌ترین هندشیک موفق انتخاب می‌شود.
- 🔌 **دو روش اتصال:** پراکسی محلی SOCKS5 و HTTP یا تونل سراسری در Linux و Windows.
- 📱 **Android و Termux:** خروجی خط فرمان Android با معماری ARM64 و بستهٔ نصب Termux؛ در Android فقط حالت پراکسی در دسترس است و تونل سراسری پشتیبانی نمی‌شود. خروجی Android فایل APK نیست.
- 🔑 **مدیریت پروفایل:** انتخاب دستی اندپوینت‌های فعال یا ساخت کلید WARP تازه و اعمال آن روی پروفایل همراه با نگهداری نسخهٔ پشتیبان.
- 🎨 **رابط تمام‌صفحه:** منوهای انگلیسی، صفحه‌های هم‌قالب، نوار رنگی اسکن و انیمیشن ثبت کلید و راه‌اندازی اتصال.

## 🚀 شروع سریع

### 🛠️ ساخت از سورس

برای ساخت Oberon به **Go نسخهٔ 1.25.0 یا جدیدتر** نیاز دارید.

```sh
git clone https://github.com/oberon-core/oberon.git
cd oberon
go build -trimpath -o oberon .
```

اجرای منوی تعاملی:

```sh
./oberon
```

در Windows PowerShell:

```powershell
go build -trimpath -o .\oberon.exe .
.\oberon.exe
```

## 📱 Android و Termux

ریلیزها شامل فایل `oberon-<tag>-android-arm64.tar.gz` برای اجرای خط فرمان Android و فایل `oberon-<tag>-termux-aarch64.tar.gz` همراه با نصب‌کنندهٔ Termux هستند. خروجی Android فایل APK نیست.

در Termux بسته را استخراج و Oberon را در پوشهٔ `bin` نصب کنید:
به‌جای `<tag>` نام تگ نسخهٔ موجود در فایل دانلودشده را قرار دهید.

```sh
tar -xzf oberon-<tag>-termux-aarch64.tar.gz
bash ./install-termux.sh
oberon --version
```

در Android فعلاً از حالت پراکسی محلی استفاده کنید. برای ساخت پروفایل و اتصال با SOCKS5 و HTTP:

```sh
oberon warp create -out warp-awg.conf
oberon connect -config warp-awg.conf -socks 127.0.0.1:1717 -http 127.0.0.1:1718
```

خروجی Android مسیرهای شبکهٔ سیستم را تنظیم نمی‌کند و رابط TUN سراسری نمی‌سازد.

## ▶️ اتصال با TUI

برنامه را بدون آرگومان اجرا کنید و گزینهٔ **Connect Oberon** را بزنید:

1. Oberon کنار فایل اجرایی یا در پوشهٔ فعلی دنبال پروفایل معتبر `.conf` می‌گردد.
2. اگر پروفایلی نباشد، یک‌بار حساب WARP را ثبت و پروفایل را ذخیره می‌کند. ابتدا پوشهٔ فایل اجرایی را امتحان می‌کند و اگر پوشهٔ فعلی جدا باشد، آن را هم امتحان می‌کند.
3. پیش از هر اتصال اندپوینت‌ها را اسکن و سریع‌ترین هندشیک موفق را انتخاب می‌کند.
4. هر دو پراکسی محلی را راه‌اندازی می‌کند.

صفحهٔ اتصال، اندپوینت انتخاب‌شده و اطلاعات پراکسی را نشان می‌دهد:

| پراکسی | نشانی پیش‌فرض |
| --- | --- |
| SOCKS5 | `127.0.0.1:1717` |
| HTTP | `http://127.0.0.1:1718` |

پس از اتصال، صفحه اندپوینت و هر دو نشانی پراکسی را نشان می‌دهد و در پایان **Oberon Connected** را نمایش می‌دهد.

کلید ذخیره‌شده در اتصال‌های بعدی دوباره استفاده می‌شود. برای ساخت کلید تازه، گزینهٔ **Create WARP Key & Apply** را بزنید؛ نسخهٔ قبلی پروفایل با پسوند `.bak` نگه داشته می‌شود.

گزینهٔ **Scan Endpoint & Manual Connection** اندپوینت‌های فعال را فهرست می‌کند تا با کلیدهای جهت‌نما یکی را انتخاب و با همان وصل شوید. اگر جابه‌جایی با کلیدهای جهت‌نما در دسترس نبود، اندپوینت را با شماره انتخاب کنید.

## 💻 راهنمای CLI

| دستور | عملکرد |
| --- | --- |
| `oberon` یا `oberon tui` | باز کردن منوی تعاملی. |
| `oberon create -out warp-awg.conf` | ثبت پروفایل WARP، اسکن اندپوینت‌ها و ذخیرهٔ نتیجه. |
| `oberon scan -config warp-awg.conf -mode fast` | اسکن پروفایل و نمایش اندپوینت‌های فعال. |
| `oberon scan -config warp-awg.conf -P -o selected.conf` | ذخیرهٔ یک کپی از پروفایل با سریع‌ترین اندپوینت موفق. |
| `oberon connect -config warp-awg.conf` | اسکن و راه‌اندازی تونل سراسری. |
| `oberon connect -config warp-awg.conf -socks 127.0.0.1:1717 -http 127.0.0.1:1718` | اسکن و راه‌اندازی پراکسی‌ها با تونل درون‌حافظه‌ای. |
| `oberon --version` | نمایش نسخهٔ Oberon و هدف ساخت. |

`oberon warp create` نام جایگزین برای `oberon create` است. دستور قدیمی `oberon run profile.conf` نیز پشتیبانی می‌شود.

### 🔌 اتصال فقط با پراکسی

یکی یا هر دو گزینهٔ پراکسی را استفاده کنید:

```sh
oberon connect -config warp-awg.conf -socks 127.0.0.1:1717
oberon connect -config warp-awg.conf -http 127.0.0.1:1718
oberon connect -config warp-awg.conf -socks 127.0.0.1:1717 -http 127.0.0.1:1718
```

حالت پراکسی از تونل درون‌حافظه‌ای استفاده می‌کند؛ مسیرهای شبکهٔ سیستم را تغییر نمی‌دهد، به دسترسی Administrator یا root نیاز ندارد و از Wintun استفاده نمی‌کند.

### 🔎 حالت‌های اسکن

- `-mode fast` مجموعهٔ منتخب اندپوینت‌های Oberon را بررسی می‌کند.
- `-mode all` نشانی‌ها و پورت‌های بسیار بیشتری را بررسی می‌کند و ممکن است زمان‌بر باشد.
- `-workers` تعداد بررسی‌های هم‌زمان و `-timeout` مهلت هندشیک هر اندپوینت را تعیین می‌کند.

```sh
oberon connect -config warp-awg.conf -mode all -workers 24 -timeout 1s
```

هندشیک موفق، دسترسی و تأخیر اندپوینت را می‌سنجد و معیار سرعت دانلود یا آپلود نیست.

## 🛡️ پیش‌نیاز تونل سراسری

حالت سراسری مسیرهای شبکه را تغییر می‌دهد و به دسترسی سطح بالا نیاز دارد:

- **Linux:** دستور را با دسترسی root اجرا کنید؛ برای نمونه `sudo ./oberon connect -config warp-awg.conf`. دستور `ip` از بستهٔ iproute2 نیز باید در دسترس باشد.
- **Windows:** Oberon درخواست دسترسی را خودکار با UAC نمایش می‌دهد. فایل DLL متناظر **Wintun 0.14.1** باید کنار `oberon.exe` باشد.

از پوشهٔ پروژه، اسکریپت نصب آرشیو Wintun را دریافت می‌کند، هش SHA-256 را بررسی می‌کند و DLL را نصب می‌کند:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\setup-wintun.ps1 -Architecture amd64
```

برای ساخت‌های Windows با معماری‌های دیگر از `arm64`، `x86` یا `arm` استفاده کنید. اگر `oberon.exe` در پوشه‌ای جدا از پروژه است، `wintun.dll` را کنار فایل اجرایی کپی کنید.

اسکریپت ساخت، هدف‌های Linux، Windows، macOS، FreeBSD و OpenBSD دارد؛ راه‌اندازی مسیر سراسری فعلاً در Linux و Windows پیاده‌سازی شده است.

## 🧪 ساخت و آزمایش

```sh
go build -trimpath -o oberon .
go test ./...
bash ./scripts/build-matrix.sh ./dist
```

اسکریپت ماتریس ساخت برای پوسته‌های POSIX است. در Windows می‌توانید با Go مستقیم بسازید یا متغیرهای هدف ساخت را در PowerShell تنظیم کنید.

## 🔐 امنیت و نگهداری پروفایل

- فایل `.conf` شامل کلید خصوصی است. آن را محرمانه نگه دارید و پروفایل، فایل پشتیبان `.bak` یا کلید را در مخزن عمومی منتشر نکنید.
- پراکسی‌های محلی احراز هویت ندارند و فقط روی نشانی‌های loopback اجرا می‌شوند؛ آن‌ها برای برنامه‌های روی همان رایانه هستند.
- پراکسی‌ها ترافیک TCP را عبور می‌دهند و برای استفادهٔ عمومی در شبکه طراحی نشده‌اند.

## 🧰 عیب‌یابی

- **پروفایل پیدا نمی‌شود:** فایل `.conf` معتبر را کنار `oberon` یا `oberon.exe` قرار دهید یا برنامه را از پوشهٔ حاوی پروفایل اجرا کنید. در اولین اتصال TUI خودش پروفایل می‌سازد.
- **هیچ اندپوینتی هندشیک نمی‌دهد:** دسترسی شبکه را بررسی کنید، `-mode all` را امتحان کنید یا بعداً دوباره اسکن کنید؛ دسترس‌پذیری اندپوینت‌ها تغییر می‌کند.
- **ثبت حساب ناموفق است:** DNS و دسترسی به سرویس ثبت WARP را بررسی کنید.
- **خطای دسترسی یا آداپتور در Windows:** درخواست UAC را تأیید کنید و مطمئن شوید DLL نسخهٔ Wintun 0.14.1 کنار فایل اجرایی است.
- **پورت پراکسی اشغال است:** با `-socks` یا `-http` یک پورت دیگر روی loopback انتخاب کنید.

برای گزارش مشکل، سیستم‌عامل، معماری، نسخهٔ Oberon، دستور اجراشده و متن خطا را بفرستید. پیش از ارسال، کلیدهای خصوصی و شناسه‌های حساب را از لاگ‌ها و پروفایل حذف کنید.
